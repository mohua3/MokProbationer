# 复盘沉淀功能 · 技术方案（v1.0）

> 状态：草案评审 | 关联页面：`复盘沉淀中心-交互原型.html` / `影视编导桌面智能体-复盘沉淀中心.html`
> 技术栈：Tauri 2（Rust 核心）+ 国内主流 LLM + 本地向量库/ SQLite

---

## 一、功能定位

在影视编导桌面智能体中提供一个**独立窗口「复盘沉淀中心」**，将一次成功的对话/工作流经验沉淀为可复用的能力资产：

```
对话记录 ──→ 知识卡片（多技能点） ──→ 工作流知识库 ──→ 一键封装为 Skill ──→ 会话复用
```

**核心价值**：把「这一次做得好」转成「下一次自动能做得好」，与主界面「评审 · 迭代」共同构成能力自增强闭环。它是系统"越用越强"的数据引擎。

---

## 二、三个关键数据模型

### 2.1 `WorkflowNode`（工作流执行节点——对话/产物溯源）

复盘的第一步是"总结对话记录"，为此需要把一次会话还原成可分析的结构。每个节点对应当前 Agent 循环中的一次工具调用或一个产物产出。

```jsonc
{
  "node_id": "wf_8f2c1a",
  "session_id": "sess_0312",
  "type": "tool_call",                      // tool_call | artifact | llm_turn
  "agent": "storyboard_agent",              // 触发的子 Agent
  "tool": "storyboard_updater",             // 具体工具
  "args_snapshot": { "scene": 3 },           // 入参摘要
  "produced_artifacts": ["art_ff1"],        // 关联产物
  "result_status": "applied",               // applied | reverted | draft
  "user_verdict": "accepted",               // accepted | edited | rejected | null
  "ts": 1752120000000
}
```

> 来源：Agent 核心层的执行循环（Tool-call 日志）自动落库，无需用户手动记录。这是"一键总结"能成立的前提。

### 2.2 `KnowledgeCard`（知识卡片——一技能一点，多技能点组成一次复盘）

关键设计：**一次复盘产出一张总览 + 多张技能点子卡**。每张技能点卡聚焦单个可复用的能力点，可独立沉淀、独立封装。

```jsonc
{
  "card_id": "kc_09",
  "skill_point": "分镜脚本优化",            // 技能点名（区别于流程名）
  "origin": {
    "sessions": ["sess_0312"],
    "summary": "一次把分镜按三情(铺垫/冲突/释放)拆分的优化过程"   // STEP01 的 LLM 总结
  },
  "trigger": "分镜需按情绪拆分",            // 触发场景
  "interface": { "inputs": ["剧本段落", "分镜JSON"], "outputs": ["优化分镜", "提示词"] },
  "steps": [                                // 操作流程（可人工编辑）
    { "order": 1, "action": "解析剧本段落，抽取情绪与叙事节点", "tool": "解析器" }
  ],
  "prompt_template": "按\"铺垫/冲突/释放\"三段切分本镜序列……",   // 关键提示词模板
  "best_practices": ["情绪转折点拍慢", "对白前给反应镜头"],
  "metrics": {
    "regression_stability": "3/3",          // 回归通过比例（Evals）
    "reuse_count": 0
  },
  "state": "drafted",                       // drafted | saved | packaged
  "created_at": 1752120000000
}
```

### 2.3 `SkillSpec`（Skill 封装——对外可调用单元）

当知识卡片通过回归、可对外复用时，封装为标准 Skill 格式。

```jsonc
{
  "skill": {
    "name": "storyboard-optimize",
    "description": "当需要按情绪拆分分镜时，复用本脚本……",
    "version": "1.0.0",
    "source_cardId": "kc_09",
    "workflow": [
      { "step": "parse", "agent": "script_parser" },
      { "step": "split_by_emotion", "agent": "storyboard_agent" },
      { "step": "compose_shot_directives", "agent": "directing_agent" },
      { "step": "consistency_check", "agent": "asset_checker" }
    ],
    "entry_trigger": "/workflow:storyboard-optimize",   // 会话内一键调用入口
    "prompts": { "template": "……", "variables": ["分镜JSON"] }
  }
}
```

**封装触发连锁**：`SkillSpec` 由 `KnowledgeCard` 编译生成，同时产物写成 `prompts/*.md` / `workflows/*.json` 落盘到 `$APP_DIR/skills/<name>/`，便于版本管理。

## 三、四步处理管线（对应 UI 三步流程）

### PHASE 1 · 对话还原与总结（STEP 01）

- **输入**：选定会话的 `WorkflowNode[]` 序列 + 原始消息。
- **处理**：LLM 以结构化 prompt 归纳 ——
  1. 提取**操作流程**（按时间序的步骤顺序）
  2. 识别**使用的工作流工具**（`node.tool` / Agent 名）
  3. 统计**产出的产物**（`produced_artifacts` 映射到实际文件）
- **输出**：会话级摘要（总览卡雏形）。

### PHASE 2 · 技能点拆分（STEP 02）

- 将总览摘要按"单个可复用能力点"拆分为 `n` 张 `KnowledgeCard`（复用 LLM 的 few-shot + schema 约束，保证字段稳定）。
- **人工可编辑**：步骤顺序、prompt 模板、最佳实践均可修订——人工修订即为高质量标注（反馈数据）。

### PHASE 3 · 沉淀入库（STEP 02/03）

- `state: drafted → saved`，写入**工作流知识库**：
  - **向量索引**（RAG）：`steps` / `prompt_template` / `trigger` 嵌入，供后续检索复用。
  - **关系存储**（SQLite）：卡片 ↔ 会话 ↔ 产物 ↔ Skill 的引用关系。
  - **样本归档**：该卡片对应的 `WorkflowNode[]` + `user_verdict` 作为后续微调采样来源。

### PHASE 4 · 一键封装 Skill（STEP 03）

- 满足条件（`regression_stability` 达标 或 人工勾选"强制封装"）→ 编译 `SkillSpec`。
- 写入 `skills/` 目录 + Skill 资产库索引。
- 会话内通过 `entry_trigger` 可**一键复用**，每次成功复用回写 `reuse_count`，形成"沉淀—复用—再沉淀"循环。

---

## 四、知识库检索与复用（技术落点）

| 需求 | 方案 |
|------|------|
| 向量存储 | 本地 `sqlite-vec` / `lance`（轻量，随 Tauri 打包）；大规模可换 `Qdrant` |
| 嵌入模型 | 国内 embedding（如 `text-embedding-v3` / `BGE-M3`），多模态可叠加 `CLIP` |
| 检索策略 | hybrid BM25 + 向量；命中 `trigger` 后返回 top-k 卡片 |
| 复用入口 | 主会话触发 `/workflow:<skill>` → 加载 `SkillSpec` → 展开 Agent 调用链 |
| 隐私/数据 | 全部本地保存，支持导出 `skills/` 为独立资产包 |

## 五、数据流与系统集成

```
[Agent核心·Tool-call日志] ──workflow nodes──► [会话]
        │                                       │ 设定/拖入选定对话
        ▼                                       ▼
[向量库 + SQLite] ◄──保存── [KnowledgeCard] ◄──[LLM 提炼(STEP01-02)]
        ▲                     │ step03
        │                     ▼
[检索复用] ◄──加载── [SkillSpec] ──编译──► [skills/ 目录] ──► [主会话一键调用]
```

**集成点**：
1. **入口**：主界面左栏「♻ 复盘沉淀中心」+ 会话头部「对话 → 复盘沉淀」唤起独立窗口。
2. **数据**：读 `WorkflowNode` 日志表；写 `KnowledgeCard` / `SkillSpec` 表。
3. **闭环**：Skill 复用 → 新一轮 Tool-call 日志 → 再次可被复盘，形成增强引擎。

## 六、风险与缓解

| 风险 | 缓解 |
|------|------|
| LLM 提取结构不稳定 | 用 JSON-Schema 约束输出 + few-shot；解析失败回退"人工粘贴总结" |
| 技能点拆分粒度过细/失真 | 提供"合并/拆分/重命名"操作；以 `reuse_count` 反向淘汰低效卡 |
| 自动封装带来误用 | 封装需回归达标或人工确认；Skill 变更走版本号 + 差异 diff |
| 知识库膨胀 | 卡片 TTL / LRU 淘汰 + 定期归并相似卡（向量去重） |
| 训练样本污染 | 仅归档 `user_verdict === accepted` 的样本；人工修订样本优先 |

---

## 七、结论与下一步

复盘沉淀功能**技术完全可行**，核心数据模型（`WorkflowNode` → `KnowledgeCard` → `SkillSpec`）已闭环，且天然复用系统已有的执行日志、向量库与微调生态。它是把智能体从"能用"推向"越用越强"的关键模块。

**建议落地顺序**：
1. **M1 数据层**：`WorkflowNode` 落库 + `KnowledgeCard`/`SkillSpec` Schema + SQLite/向量读写
2. **M2 提炼管线**：PHASE 1–2 的 LLM 提取（含 schema 约束）——这是技术风险最集中点，优先验证
3. **M3 封装复用**：Skill 编译落盘 + 会话触发链路
4. **M4 闭环增强**：回归(Evals) + `reuse_count` 淘汰 + 样本采样接微调

> 说明：本文档为方案层描述，位于 `design/` 目录与 UI 设计稿并列。进入实现前建议先对 M2（LLM 提取）做一次可运行验证。
